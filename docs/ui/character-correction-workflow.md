# 角色身份与纠错修改流程

授权：2026-09-10 用户要求根据《翠玉录重复角色检查》生成流程并实施。按依赖拆为连续切片，逐项 DoD、实现、验证与独立提交，不自动修改真实作品。

1. I219：阻止跨阶段重复主角；修正错误的“没有主角”提示；基础资料候选可选择复用，失败保留基础资料，只重试大纲/揭示；合并前再次校验，所有写入仍经 I11。
2. I220：角色引用影响预览、冻结/恢复及受控删除；保留历史记录和可恢复资料，明确被冻结角色被当前任务引用时的处理，strict additive IPC 与真实桌面验证。
3. I221：重复角色合并预览、资料冲突选择、当前引用迁移及历史身份留存；不机械合并知情，不替换历史正文字符串。按当前领域 owner 的可恢复事务实施。

生成方面先维护一致身份，不额外增加 LLM 调用。主角复用是作者在候选阶段的明确选择，最终计划确认展示实际角色与身份，不改变此前来源审阅记录。
