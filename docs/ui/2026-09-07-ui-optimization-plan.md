## 1. 结论与证据

现有产品已具备“纸、墨、朱砂”的品牌基础，也有完整的作者流程。问题主要出在桌面迁移后的样式作用域、主次关系和页面组合：作品与正文没有稳定占据视觉中心，功能入口和辅助面板抢占注意力，部分实际入口绕开了已有样式。

| 优先级 | 观察 | 源码证据 | 对作者的影响 | 设计处理 |
| --- | --- | --- | --- | --- |
| P0 | 桌面作品目录按钮缺少 className，含 `Select DOCX import` | `src/desktop/renderer/shell.ts` 的 `projectDirectoryView` | 进入应用即出现默认控件与中英混排，缺乏品牌与统一性 | 作品库统一 PageHeader、ProjectCard、Button；改为“导入 DOCX” |
| P0 | 主题变量只定义于 `.nv-workbench`；作品目录、助手、迁移、流式提示不全在其后代内 | `styles/base.ts`、`shell.ts` 的三个视图组合及末尾返回结构 | `--nv-*` 引用可能失效，颜色、间距和字体不一致 | 将语义 token 放在每个桌面 shell 的共同根节点；所有浮层继承或显式挂在同一主题根下 |
| P0 | 外壳固定深色，暗色强调色选择器依赖未见桌面设置的 `body[data-ds-dark-theme]` | `renderer.css`、`styles/responsive.ts` | 暗底可能使用亮色主题的深朱砂，选中态和焦点弱 | 桌面根明确消费一套完整色表；提案先以暖纸视觉统一，不顺带实现主题设置系统 |
| P0 | 正文主区内还有 `220px 220px minmax(0,1fr)` 三栏 | `styles/chapters.ts:13` | 加上全局导航后正文被挤窄，窗口缩小时更明显 | 章节与场景合为一棵树，正文居中，助手按需展开 |
| P0 | 工作台采用 fixed 全屏，助手是其兄弟，迁移面板始终挂载在根下 | `shell.ts` 的 `structuredProjectView`、`DesktopWorkbenchShell`；`styles/base.ts` | 存在遮挡和可达性风险，需在真实窗口验证 | 助手移入工作区侧栏/抽屉；迁移收纳到作品库工具入口，打开时才占据内容区 |
| P1 | 19 个导航入口虽已分组，当前任务还只是标题、文字和普通步骤列表 | `nav.ts`、`layers/workflow.ts` | 用户需自行扫描才能确定下一步 | 保留四组和 route，当前任务用大卡片及唯一主按钮强调；进阶组默认可折叠 |
| P1 | 页面标题多为 16–17px，字段 12–13px，`.nv-btn` 通用样式位于 chapters 分区 | `styles/base.ts`、`styles/forms.ts`、`styles/chapters.ts` | 主体和辅助文字接近；控件规则缺少明确 owner | 标题 28px、分区 18px、控件 14px；公共控件由独立视觉组件层负责 |
| P1 | 队列失败、候选待处理、运行中均使用朱砂 | `styles/panels.ts` | 成功/等待/错误难以区分 | 朱砂仅用于行动；状态另用成功绿、信息蓝、警告琥珀、危险红，配图标和文字 |
| P1 | AI 设置写着“重启 DSH”“不回传浏览器” | `src/client/settings.ts` | 桌面产品身份与凭据说明陈旧 | 按实际发布基线重写说明；v4.1 profiles 界面单列后续依赖 |
| P1 | 按钮用“删”“改写”“提交一次确认”等含混文案 | outline/worldview/chapters 等面板 | 不清楚对象、结果与是否会写入 | 使用“动词＋对象”，提案、审阅与最终写入分别命名 |
| P2 | 工作台仍有“折叠/关闭/悬浮砚入口”的旧侧板语义 | presenter、base styles | 与 Electron 应用窗口控制混淆 | 后续 shell 切片中改为导航收起/展开；应用关闭使用系统标题栏，保留兼容锚点迁移说明 |

审查边界：以上首先来自源码与 DOM 组合分析；不把“可能被遮挡”写成已在用户真实安装包复现。原型截图是目标设计效果，不能作为现状截图。按钮清单含兼容和未接入函数，明确标注，不能把声明数量当成同屏按钮数量。

## 2. 设计方向：让作品成为主角

沿用设计 §14.6 的书斋气质：暖纸背景、墨色标题、朱砂主操作。作品名、当前章节和正文构成第一视觉层；工具、统计和诊断退到第二、第三层。页面使用平整工作面和必要分隔，避免把每段信息都装进同样的卡片。

每页回答三个问题：“正在处理什么”“现在处于什么状态”“下一步做什么”。一个当前任务区域最多一个实心主操作；一个模态确认出现时，背景任务操作不可交互。列表新增和表单保存可以属于不同状态，但不同时争夺一级视觉。

| `--ui-warning` / 背景 | `#815914` / `#FBF0D9` | 未决、阻塞、软警告 |

标题使用现有系统衬线栈；界面使用现有系统无衬线栈。字号：作品标题 32/40、页面标题 28/36、分区标题 18/28、UI 14/22、辅助 12/18；正文编辑与阅读 18/34，中文行宽约 32–40 字，正文面宽 640–760px。无需网络字体与位图背景。

8px 基础网格，允许 4px 半格；页面 padding 32px，紧凑窗口 20px；分区间 24px，字段间 16px，按钮间 8px。控件圆角 8px，卡片 12px；仅弹窗和浮层使用明显阴影。图标为同一套本地线性 SVG，18px、约 1.75px stroke；图标辅助文字，不使用 emoji 作为正式导航图标。

暖纸方案是本次推荐的单套桌面外观。深色外观可在后续复用相同语义 token；本次不将此前后置的主题引擎默认为已获实现排期。

### 2.2 应用框架与尺度

| 区域 | 尺度 | 内容与行为 |
| --- | --- | --- |
| 系统标题栏 | 保持 Electron/系统既有行为 | 应用名称和原生窗口按钮；不在页面再放“关闭应用” |
| 全局导航 | 216px，行高 40px | 作品切换、创作流程、故事资料、进阶工具、设置；活动项浅朱砂底＋左标记＋较粗文字 |
| 页面头部 | 随内容 88–112px | 路径/作品上下文、标题、一句目标说明、主操作 |
| 当前任务区 | 内容首屏最显著区域 | 当前对象、状态、下一步；避免同时堆满八个阶段操作 |
| 章节/资料列表 | 232–264px | 搜索仅在已有可用数据范围内作为 UI 筛选；选择行显示明确选中态 |
| 正文/表单 | 可伸缩主列 | 正文优先；表单宽度通常 ≤760px |
| 辅助栏 | 288px，可收起 | 当前细纲、角色与助手；不能成为领域数据副本 |
| 页内操作栏 | 最小 64px | 长表单/审阅固定在内容区底部，显示未保存或待确认数量 |

≥1440px 可展示导航＋对象树＋正文＋辅助栏；1100–1439px 自动收起辅助栏；900–1099px 对象树可折叠为选择器；<900px 使用导航抽屉及单主列。720px/440px 的兼容窄窗仍验证可达性，不承诺移动端产品。任何宽度都不能仅靠横向滚动寻找主操作。200% 缩放时允许列堆叠和底栏增高，禁止遮住焦点控件。

### 2.3 保留的导航与概念

保留 `workflow / story / advanced / settings` 四组与 19 个导航入口，隐藏兼容 `onboarding` 仍由导入阶段到达，共 20 个稳定 view。正文四种模式保留为页内 tab。八阶段依旧是导入→大纲→细纲→生成基线→正文→定稿同步→全书检查→导出。

“继续当前任务”投影既有 workflow resume，不能新建另一套业务进度。八阶段的“当前位置”不等于业务验收通过；没有真实完成证据时只显示“已访问/当前/未访问”，不能仅按阶段序号涂绿为已完成。

| 规则与文风 / ruleStyle | 规则列表与文风档案两个页内 tab；长字段分组 | 保存当前规则 / 保存文风档案 | 新建规则、编辑、取消；规则初始化生成只留首次导入 | 空、只读规则、编辑中、保存成功/失败 |
| 进度与灵感 / progress | 当前执行卡、偏差记录、灵感方向分区；选中方向展开详情 | 当前子区“记录偏差”或“获取灵感” | 标记已调和、选择方向、审阅应用、不采用 | 无偏差、生成中、方向待选、待确认、失败 |
| 搜索与追踪 / search | 大搜索栏＋范围过滤＋结果/引用详情 | 搜索 | 查看引用、跳转；重建/删除索引放维护折叠区 | 未搜索、无结果、加载、结果失效、索引不可用 |
| 写作进度 / statistics | 总字数/目标完成度/章节进展三项摘要；章节表和分布图 | 查看章节详情（链接式，不强制实心按钮） | 刷新概览；重建/删除统计放维护区 | 无正文、过期、重建中、失败；统计来源解释在辅助区 |
| 导入导出与备份 / importExport | 默认“全文导出”；另两个分区“项目备份”“恢复与兼容导入” | 按选中格式导出全文 | TXT/Markdown 为选项，不并排两个主按钮；项目包说明含完整作品数据 | 就绪检查未通过、导出中、完成、失败、恢复影响确认 |
| 创作设置 / creationSettings | 短表单，目标字数与补充素材策略；作用范围写明 | 保存创作设置 | 打开作品文件夹为次操作 | 未选作品、未保存、保存中、失败 |
| AI 设置 / settings | 服务地址/模型/密钥为基本区；输出长度/思考参数为高级区 | 保存 AI 设置 | 当前实现只设计已存在的保存；多 profile/连接测试不冒充已有能力 | 密钥已有/待录入、无效参数、保存中、失败、需生效处理 |
| 创作助手 / DesktopAssistantPanel | 抽屉/辅助栏，当前场景为上下文；结果与候选占主体 | 生成续写候选→接受候选 | 查看上下文/状态为轻操作，灵感另一区；避免与正文候选同时出现两个生成主按钮 | 未选择作品、处理中、候选、错误、空结果 |
| 旧作品迁移 / DesktopMigrationPanel | 作品库工具入口进入专用页，展示源库检查、复制计划、结果 | 检查旧库→确认复制 | 回滚本次迁移进危险区；说明旧源保持不变 | 未检查、无旧库、冲突阻塞、待确认、复制中、成功/失败 |
| AI 任务进度 / DesktopLlmStreamWindow | 页内状态条＋可展开详情；仅非阻塞任务可折叠 | 没有人工动作时不强加主按钮 | 取消仅绑定真实支持的取消方法；不能只有旋转图标 | 检查配置、连接、推理、接收字数、校验、失败、完成 |
| 全局异常与离开确认 / presenter＋scene-editor | 就地错误；离开风险用紧凑对话框，写明对象和未保存内容 | 安全默认：继续编辑；破坏动作：放弃修改并离开 | 返回来源、知道了、重试；错误详述按已有脱敏机制 | 连接中断、跨项目失效、脏表单、重复提交 |

## 4. 所有按钮的统一设计合同

### 4.1 级别与尺寸

| 编码 | 类型 | 样式 | 位置与用途 |
| --- | --- | --- | --- |
| P | 主操作 | 朱砂底、白字、14px/600、40px 高，左右 16px | 页头或任务底栏右侧；当前任务一个 |
| S | 次操作 | 纸面底、墨字、控件边框、40px 高 | 主操作左侧；新增/预览/对比/手动编辑 |
| T | 轻操作 | 透明底、墨色次级字、hover 浅底、32px 高 | 列表行、刷新、关闭、更多菜单 |
| D | 危险操作 | 默认危险红文字/边框，确认页危险红实心 | 对象更多菜单或危险区；与日常操作隔开 |
| N | 导航/对象选择 | 40px 行高、左对齐、选中浅朱砂底＋标记 | 导航、章节树、版本行；绝不伪装成提交按钮 |
| C | 分段/裁决选择 | 36px 高；选中填浅色并带勾/文字 | 模式 tab、按事实/角色、保留/排除、润色类型 |
| I | 图标工具 | 32×32px 热区、18px 图标、tooltip、可访问名称 | 帮助、对象移动、关闭辅助面板 |

列表操作可用 32px 紧凑尺寸，启动/空态 CTA 可用 44px；不得通过缩小字号解决按钮拥挤。可点击目标内部建议 ≥32×32px；本项目采用 32px 下限与 40px 常规按钮，比 WCAG 2.2 的 24×24 CSS px 最小目标（含例外条件）更宽裕。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### 4.2 全状态规则

| 编码 | 规则 |
| --- | --- |
| G0 | 所有按钮具有 default/hover/pressed/focus-visible/disabled；2px 可见焦点环及 2px offset。disabled 不只降低透明度，邻近说明原因；按钮宽度在忙碌时稳定 |
| G1 | 保存类：未修改禁用并说明；保存中“正在保存…”防重入；成功状态就地显示且保留对象；失败保留输入并可重试；不引入隐式自动保存 |
| G2 | 生成类：明确范围/输出是候选；忙碌显示真实阶段和可用取消；失败只重试原操作；零未经确认写入 |
| G3 | 提案/确认类：保留现有 propose→review→accept；主按钮随阶段替换，确认页必须给出对象、变化、影响；复用 I11；未决/陈旧/部分失败阻塞及恢复如实呈现 |
| G4 | 导航/选择：当前态可见、键盘可达、长名截断可查看全名；离开脏草稿走原保护；选择不产生额外领域写入 |
| G5 | 危险类：清晰对象、影响和不可逆性；确认默认焦点在取消/继续编辑；Host 最终校验；拒绝与取消不包装成删除 |
| G6 | 工具/只读查询：操作区域显示 loading/empty/error，失败保持原结果并标“未更新”；重建/清空派生数据不暗示删除正文 |
| G7 | 任务控制：暂停/继续/取消互斥可用，忠实映射任务状态；不通过再次点击启动重复任务；取消结果由 Host 确认后显示 |
| G8 | 本地裁决/编辑：选中状态用样式＋文字；保留/排除均可重新选择；“未决”与“已排除”视觉不同；调整后重新计算确认可用性 |
| G9 | 作品生命周期：归档/恢复显示作品对象；请求期间防重入，完成后更新目录与只读状态；失败保留原目录并显示原因；只复用既有保护，不因统一外观凭空添加二次确认 |

Modal 的 Tab 焦点限制于对话框，Esc 遵循可取消性，关闭后焦点回原触发器；非模态助手不锁定主界面焦点。[W3C 对话框交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

### 4.3 文案规范与边界

- “保存”→“保存角色/保存关系/保存时间点”；“改写”→“保存设定”；“删”→“删除幕”；“删节”→“删除节”。
- “确认候选”必须结合当前服务真实写入范围命名；正文候选继续使用“接受为草稿”。不能把所有接受按钮统一成“完成”。
- “提交一次确认”展示为“审阅同步方案/审阅调整方案/审阅删除影响”，点击仍绑定原提案调用，不省去最终确认。
- “拒绝候选”可展示“不采用候选”；“排除此段”是导入选择，不用危险红实心；“删除章节”是真实危险操作，使用 D。
- “取消”区分“取消生成”“取消审阅”“继续编辑”；禁用原因如“还有 3 段未确认”“请先保存大纲”“请先选择场景”。
- 普通页面不出现 IPC、Host、fingerprint、内部 ID、B/C 层代码、主进程等实现文字；诊断只在明确辅助区展示脱敏信息。
- AI 设置文字依据实际运行版本：v4.1 明文 profiles 落地后必须明确密钥是本机明文存储；不得沿用“安全存储”或“不回传浏览器”。当前包不能提前宣称已具备多 profile。

## 5. 组件与实施边界

建议后续在 `src/desktop/renderer/ui/` 建公共视觉组件，在现有 React/createElement 方式下工作：Button、IconButton、PageHeader、Section、Field、StatusBadge、EmptyState、InlineError、ActionBar、Tabs、Drawer，以及 ConfirmationGate 的呈现适配器。不引入另一套路由或状态库。

`renderer.css` 负责 shell 根和语义 token；现有 `src/client/styles/*` 逐个切片迁移消费，不再由 `chapters.ts` 持有全局 Button owner。允许短期由 `--nv-*` 映射到 `--ui-*`，但仅一个真实色表 owner，退役边界写入正式卡。每个 `data-novel-*` 锚点及事件方法保持，必要 DOM 锚点迁移先列清调用消费者。

助手和迁移的放置调整属于 Renderer 呈现；新受管窗口、profile 存储和 secret-bearing IPC 另立实现卡。原型中的页切换只是设计面切换，不能拿离线 HTML 成为 Web/PWA 生产入口。

## 7. 验收矩阵

1. **视觉主体**：1366×768 和 1920×1080 下作品、当前任务、主要动作首屏可见；正文模式默认纸面为最大连续区域；没有两个抢眼的并列提交动作。
2. **页面覆盖**：19 个导航入口＋隐藏 onboarding 共 20 route；覆盖正文四模式、来源逐段审阅、首次规则文风、初始化、细纲、定稿、引用审查、助手、迁移和全局状态。
3. **按钮覆盖**：配套清单中的每个源码声明有迁移处置；循环按钮按代表实体与每个枚举分支验证；未接入函数写明保留或退役，不假设运行可达。
4. **状态覆盖**：每页 loading/empty/error/ready；写入页追加 dirty/saving/saved/conflict；LLM 页追加 queued/running/cancelled/candidate-ready；所有失败保持原数据并可执行合约允许的恢复。
5. **负向门**：无项目不写入；归档只读；缺场景/缺前置项不生成；双击不重复；取消不写入；未确认不应用；过期提案拒绝；部分应用失败如实可恢复；密钥不进入错误/进度/日志/导出。
6. **无障碍**：正文/控件普通文字对比度 ≥4.5:1，大字 ≥3:1；选中/错误不单靠颜色；键盘焦点可见；弹窗焦点可回归；错误与字段关联。指标参照 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，不是仅靠取色就宣称完整 WCAG 合规。
7. **窗口与缩放**：1920×1080、1440×900、1366×768、1024×768、720px 与 440px 窄宽兼容；Windows 100%/125%/150%/200% 缩放；长中文作品名、100 章、数十条候选等数据量。
8. **真实交付门**：每一正式切片完成后 `pnpm test` 与其 `verify:iN`；阶段结束 `verify:stage-N`、既有样本回归与 packaged-app E2E。视觉切片不修改 prompt/schema/gold/阈值，不添加为设计提案编造的验证命令。
